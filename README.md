---
## הבעיה: זיכרון מהסשן הקודם לא מספיק

זיכרון מתמשך לסוכני AI הוא נושא חם היום. אבל בפרויקט אמיתי, סשנים שבאים אחד אחרי השני בדרך כלל לא קשורים זה לזה: סשן אחד בונה פיצ'ר בממשק, הבא מתקן באג בשכבה אחרת, והשלישי נוגע במסד הנתונים. לכן זיכרון של "מה קרה בסשן הקודם" לא בהכרח עוזר לסשן הבא.

מה שכן חשוב הוא ממצא שהתגלה היום, ושיהיה נחוץ לסשן כלשהו בעתיד. לא בהכרח לסשן הבא, אלא לזה שימשיך לבנות באותו נושא, אולי בעוד שבוע ואולי בעוד חודשיים, ושההחלטות שלו צריכות להישען על מה שכבר נלמד.

## הפתרון: מסמך חי לכל נושא מורכב בפרויקט 

**מה מתעדים?** ממצאים שכנראה יהיו חשובים לסשנים עתידיים: החלטות והסיבות להן, ארכיטקטורה, מגבלות ומלכודות שכבר נתקלתם בהן.

**איפה?** במסמך ב-CodeKeeper. הסוכן מחובר אליו, ולכן הוא יכול לקרוא את המסמך ולעדכן אותו בעצמו.

**מה השיטה?** לכל נושא מורכב בפרויקט, שהמידע ההיסטורי עליו ישנה החלטות במימוש של פיצ'רים עתידיים, פותחים מסמך משלו. ואז נותנים ל-Claude Code הנחיה קבועה:

> בכל סשן שבו מצאת ממצאים חשובים על נושא X, בסוף הסשן עדכן את מסמך X עם כל הממצאים האלה.

ומגדירים לו מה נחשב חשוב ומה לא, כדי שהמסמך יישאר ממוקד ולא יתמלא ברעש.

**מה מרוויחים?** מסמך חי לכל נושא שמצריך תיעוד, שמתעדכן בכל פעם שעולה משהו חדש. כשסשן עתידי ממשיך לבנות בנושא, מפנים אותו לקרוא את המסמך, והוא מתחיל עם כל מה שכבר נלמד. ואת אותו מסמך אפשר לשלוח לכל סוכן: כשרוצים להתייעץ על המשך הפיתוח, או כשרוצים בריף איכותי באמת, שנשען על כל ממצאי העבר הרלוונטיים, כדי לשלוח אותו ל-Claude Code למימוש.

## איך זה נראה ביום-יום?

1. **בסוף משימה מורכבת:** אחרי שפיצחתם עם הסוכן באג סבוך או בניתם מנגנון חדש, מבקשים ממנו במשפט: *"תשמור ב-CodeKeeper מסמך על מערכת ה-Billing עם ההחלטות והמלכודות שגילינו היום, ותעדכן את CLAUDE.md של הפרויקט עם כלל טריגר לקריאת המסמך: כשאתה נוגע בקוד / מציע תוכנית מימוש - שנוגעים למערכת ה-Billing | קרא קודם כל את מסמך X ב-CodeKeeper"*.
2. **בתחילת משימה עתידית:** בעוד חודש, בסשן חדש לגמרי שלא זוכר כלום, אתם מבקשים משימה שנוגעת ל-Billing. הסוכן קורא אוטומטית את המסמך בנושא, ונמנע מהמלכודות שכבר נפלתם בהן.
3. **בסיום העבודה:** אם השתנתה החלטה או התגלתה מלכודת חדשה, הסוכן מעדכן את הסעיף המתאים במסמך בעצמו — בלי שתצטרכו לתחזק תיעוד ידנית. (הנחו אותו לכך כמובן, ב CLAUDE.md של הפרויקט).

## מה נכנס למסמך תיעוד מסוג כזה ומה לא 

| נכנס | לא נכנס |
|---|---|
| החלטה והנימוק שלה ("בחרנו X ולא Y כי Y שובר את Z"), כולל המחיר שהתקבל עליה במודע | סיכום של מה נעשה בסשן |
| חלופה שנשקלה ונפסלה, או בקשה של סוכן שנדחתה — עם הנימוק ("נדחה: X, כי Y"), כדי שהסשן הבא לא יציע אותה מחדש | התקדמות, סטטוס משימות, "עבדנו על..." |
| הנחה שההחלטה נשענת עליה, והתנאי שבו היא מפסיקה להחזיק ("נכון כל עוד רץ מופע אחד של השירות"; "נשען על התנהגות פנימית של ספרייה בגרסה X — לבדוק מחדש בשדרוג") | לקח שמתויק לפי פול ריקווסט או סשן — הלקח נכנס לפרק הנושאים שלו; רשימת ה-פול ריקווסטים היא אינדקס להתמצאות בלבד |
| מלכודת שכבר הפילה ניסיון, עם הסימפטום שלה | הסבר של מה שהקוד כבר אומר בבירור |
| ממצא ידוע שהושאר לא מתוקן בכוונה — עם מספר האישו, והתנאי שידליק אותו ("לא ניתן להגעה היום; מי שנוגע במודול X — זה מחכה שם") | העתקה של קוד שלם |
| מדידה אמיתית ממערכת חיה, עם התאריך ועם השיטה או הסקריפט שמדד | מה שכבר כתוב במקום אחר (README, מסמך אחר, אישו) — מפנים אליו, לא מעתיקים |
| אינטואיציה שנשמעה סבירה והמדידה הפריכה — ההנחה ולידה המספר שהפיל אותה | מספרי שורות, מספר טסטים, וכל מספר שזז עם כל קומיט — במקומו שם סימבול, או טסט שמקבע את המספר |
| הערכה או השערה שעוד לא נבדקה, מסומנת ככזאת ("לא נמדד") | |
| מספר שנבחר בקוד (timeout, מגבלה, גודל מקסימלי) והסיבה שבחרו דווקא בו | |
| מפה: איפה בקוד נמצא כל חלק | |
| בדיקת עשן: פקודה אחת שמוכיחה שהמערכת עדיין במצב המתועד, והתוצאה שאמורה לחזור ממנה ("`curl /health` מחזיר 200 עם `version: 3`") | |
| מוסכמות שהסשנים הבאים צריכים להמשיך לפיהן | |
| תיקון לעובדה שהמסמך עצמו טען קודם — במפורש ("גרסה קודמת מנתה X — זה לא נכון, כי..."), לא מחיקה בשקט | |
| הפניה למקום שבו הנושא כבר מתועד, ומה המסמך הזה מוסיף שאין שם | |

כלל אצבע: אם סשן עתידי יקרא את השורה הזאת ויעשה משהו אחרת בגללה, היא נכנסת. אם הוא יקרא אותה וימשיך בדיוק כמו בלעדיה, היא לא.

---

**למה דווקא CodeKeeper, ולא תיקייה בריפו**

שאלה הוגנת. תיקיית `/docs` בריפו, עם הפניה מ-`CLAUDE.md`, עושה חלק גדול מאותה עבודה, ואם אתם עובדים רק עם Claude Code ורק בריפו אחד, היא אפשרות טובה. ההבדלים מתחילים כשהשימוש רחב יותר:

- **המסמך נגיש מכל סוכן, לא רק מזה שיושב בריפו.** אותו מסמך נקרא מ-Claude Code, מצ'אט ב-Claude.ai, מ-Claude Desktop, מג'ימיני ומכל לקוח אחר שמתחבר ל-MCP. גם הקריאה לפי סעיף עובדת שם: סוכן בצ'אט, שאין לו גישה לקבצי הריפו, מקבל מפת כותרות ושולף רק את הסעיף שהוא צריך. אפשר לתכנן פיצ'ר בצ'אט של קלאוד, כשהסוכן שם קורא את אותו מסמך שהסוכן בקוד יקרא אחר כך.
- **יעילות לבן אדם שצריך את המסמך.** תצוגת Markdown נקייה ונוחה לקריאה, יש איגוד מסמכים לפי נושא ב"אוספים שלי", וחיפוש טקסטואלי וסמנטי עם AI. ככה מהר ובקלות מוצאים כל מסמך שמחפשים בשביל לשלוח/להפנות לסוכן של הסשן, או לצ'אט עם Claude כדי להתייעץ איתו בנוגע למשהו או לנסח הנחיות לסוכן על בסיס המסמך.
> מעבר לזה, יש סטיקי נוטס על מסמכי מארקדאון, להערות על המסמך, 
- **מסמך אחד לכמה ריפואים.** נושא שחוצה פרויקטים, כמו תשתית משותפת או קונבנציות עבודה, לא צריך לבחור ריפו אחד שבו יגור.

- אוסף של מדריכים שימושיים שיש לך. וכן הלאה.

> 🤖 הסוכן שלך יכול לקרוא את רשימת האוספים, את רשימת הקבצים בכל אוסף ואת התוכן המלא של כל קובץ, ולעזור לך לפי מה שאתה צריך.

### 📝 סטיקי נוטס

> לפני הכל, כנס להגדרות הלוח ובחר פונט כתב יד לפתקים. זה נותן סטייל אישי, ביתי.

**מה עושים עם פתקים?**
הסטיקי הוא המקום לרעיונות, לאפיונים, לטיוטות, למשימות לסוכן, ולכל דבר שעולה לך לשמור. אפשר לפתוח לוח לכל נושא וליצור בו הרבה פתקים.
הפתקים תומכים ב-Markdown כמעט מלא, ויש בכל פתק מקום לעד 20,000 תווים, וזה הרבה. ואפשר לקבוע לפתק תזכורת ולקבל התראת פוש במועד. <!-- התקרה: MAX_NOTE_CHARS ב-sticky_notes_target.py -->

**ומה עם הסוכן?**
הסוכן יכול לקרוא פתק, לערוך אותו ולפתוח פתק חדש.

**מה עוד מגניב?**
- יש לך אפיון מלא עם הנחיות מימוש בתוך פתק, ואתה רוצה להוסיף הערה בלי לשנות כלום בתוכן? פותחים תגובה בשרשור על הפתק.
- בסשן הבא שתפתח, Claude Code יקבל מהשרת הנחיה כבר בתחילת הסשן לקרוא את התגובה בשרשור. אז שים לב לזה, ותחשוב מתי זה יעיל לך.
- ברגע ש-Claude Code מגיב בשרשור שלך, אתה מקבל התראת פוש בוובאפ. לוחצים על ההתראה, ומגיעים ישר לתגובה שלו.

## מה יש בבוט

הבוט שומר על הריפו שלך בגיטהאב:

- **גיבוי ZIP של ריפו:** הבוט מוריד את הריפו ושומר את הגיבוי בשרת.
- **שחזור ריפו מגיבוי:** מגיבוי ששמור בשרת, או מקובץ ZIP שמעלים.
- **ריפו חדש מ-ZIP:** מעלים ZIP, והבוט יוצר ממנו ריפו חדש בגיטהאב, פרטי או ציבורי, עם אותו מבנה תיקיות.

כל הפקודות: שולחים `/help` לבוט.
