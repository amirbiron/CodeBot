# ⌨️ עורך קוד (WebApp Editor)

## טעינת CodeMirror ומצב isLoading
- נטען את CodeMirror בצורה דינמית.
- אם הטעינה נכשלת → מנגנון fallback (textarea) מופעל.
- במהלך הטעינה מוצג מצב `isLoading` כדי למנוע אינטראקציה מיותרת.

```javascript
let isLoading = true;
try {
  const cm = await import('codemirror');
  // init editor...
} catch (e) {
  console.warn('Editor fallback to textarea', e);
} finally {
  isLoading = false;
}
```

## החבילה המקומית של CodeMirror, וכיוון לכל שורה
- `EditorManager` (`webapp/static/js/editor-manager.js`) טוען קודם את `webapp/static/js/codemirror.local.js`, שמגדיר `window.CodeMirror6`. רק כשהיא לא עולה הוא בונה את `window.CodeMirror6` ממודולים ב-CDN, ובמסלול הזה אין את התוספים שהחבילה המקומית מוסיפה.
- **החבילה נבנית מקובץ ה-entry** `webapp/static_build/codemirror.bundle.entry.mjs` עם `webapp/static_build/build-cm.mjs`, מהגרסאות שב-`package-lock.json`. הבנייה רצה מתוך `webapp/static_build`: esbuild כותב בחבילה הערות עם נתיבי המודולים יחסית לתיקייה שממנה רצים, ובנייה מתיקייה אחרת משנה את כל ההערות האלה. בנייה מתוך התיקייה, בלי שינוי ב-entry, מחזירה קובץ זהה בייט-בייט לזה שבריפו (נבדק באוקטובר 2026), ולכן הדיף של שינוי ב-entry הוא רק השינוי עצמו. הסקריפט `build-cm` שב-`package.json` מריץ את אותו קובץ מהשורש, ולכן הוא משנה את ההערות. מתקינים מהשורש ובונים מהתיקייה:

```bash
npm ci --ignore-scripts
cd webapp/static_build && node build-cm.mjs
```

- **`rtlExceptCodeBlocks`** (ב-entry, ומיוצא ב-`window.CodeMirror6`): העורך כולו מימין לשמאל, ורק השורות של בלוק קוד מקבלות `dir="ltr"`. בלוק קוד הוא מה שהמנתח של Markdown בעורך כבר זיהה — הצמתים `FencedCode` (בין ```` ``` ````, כולל שורות הגדר) ו-`CodeBlock` (שורות מוזחות) בעץ התחביר — ולא ביטוי משלנו. `EditorView.perLineTextDirection` גורם ל-CodeMirror לקרוא את הכיוון של כל שורה בנפרד, כך שהסמן, הבחירה והחצים עוקבים אחריו. `initEditor` עם `textDirection: 'rtl'` מוסיף אותו, ואת המחלקה `codemirror-container--rtl`, שב-`codemirror-custom.css` הופכת את העורך לימין-לשמאל ונותנת לשורה ריווח לפי הכיוון שלה (ה-`.cm-line` של CodeMirror מרווח בצדדים פיזיים, ובעורך מימין לשמאל הטקסט נצמד לגבול). בעורך הפשוט, כש-CodeMirror לא עלה, הכול מימין לשמאל: ב-textarea אין כיוון לשורה בודדת. משתמש בו העורך הציבורי (`/markdown-editor`); עמודי העריכה וההעלאה נשארים משמאל לימין, כמו עורך קוד. כשהחבילה נטענה מה-CDN, האפשרות נרשמת כאזהרה בקונסול, והעורך נשאר משמאל לימין. עד אוקטובר 2026 כל שורה קיבלה `dir="auto"` (`perLineAutoDirection`), כלומר כיוון לפי האות החזקה הראשונה בה — ושורות כמו `- [x] משימה` או שורת היישור של טבלה יצאו משמאל לימין בתוך מסמך עברי.
- **`createBasicSetup({ gutters })`** — `basicSetup` עם האפשרות להוריד את העמודה שבצד הטקסט: בלי מספרי שורות ובלי חיצי קיפול (קיצורי הקיפול במקלדת נשארים). `initEditor` עם `gutters: false` משתמש בו; העורך הציבורי מעביר אותה. הוא קיים גם במסלול ה-CDN של `loadCodeMirror`, שבונה `basicSetup` משלו.
- **הדבקה שמחליפה את כל המסמך** — לתוך עורך ריק, או אחרי "בחר הכל" — משאירה את הסמן ואת העורך בתחילת המסמך (`getFullPasteExtension`: מסנן טרנזקציות על ה-userEvent `input.paste`), ושולחת על ה-textarea את האירוע `editor:document-replaced`, שבו התצוגה החיה (`live-preview.js`) חוזרת גם היא לראש המסמך. כפתור "הדבק" מסמן את ההדבקה שלו באותו userEvent (`insertTextAtCursor`), ובעורך הפשוט `watchTextareaFullPaste` עושה את אותו דבר. הדבקה לתוך טקסט קיים לא משתנה: הסמן אחרי מה שהודבק.
- **שורת הכפתורים** (`addSwitcherButton`, ו-`codemirror-custom.css` — ההערה מעל `.editor-switcher-actions`), מימין לשמאל: "עורך פשוט / מתקדם" (`.btn-switch-editor`, לא בעורך הציבורי), "בחר הכל / העתק / הדבק" (`.editor-clipboard-actions`), "בטל / בצע שוב" (`.editor-history-actions`), ואחריהם סרגל ה-MD בקובץ Markdown (`moveToEditorRow` ב-`markdown-toolbar.js`) או כלי הקוד בקובץ פייתון (`moveToolsToEditorRow` ב-`code-tools.js`). כל פריט בגודל התוכן שלו, הם צמודים לימין, ובין כל שניים קו הפרדה — אחד לכל השורה, בצבע הטקסט שלה בעוצמה נמוכה (`--editor-divider-color`), ולכן הוא נראה בכל ערכה. כל הכפתורים באותו גובה, גם "בטל" ו"בצע שוב" שיש בהם רק אייקון: הגובה של התוכן הוא שורת טקסט (`1lh`), ולא הגובה של האייקון. **בכמה שורות** מחליט `layoutSwitcherRow`: הוא מנסה סידורים לפי הסדר ובוחר את הראשון שבו כל שורה באמת נכנסת בשורה אחת על המסך — הכול בשורה אחת; אחרת המתג, "בטל / בצע שוב" ו-MD בשורה הראשונה ו"בחר הכל / העתק / הדבק" בשנייה; ואחרת MD בשורה משלו, בין השתיים. בעורך הציבורי, שאין בו מתג, "בחר הכל / העתק / הדבק" נשארים ראשונים ו"בטל / בצע שוב" יורדים מתחתם. ההחלטה לפי מה שנכנס ולא לפי רוחב מסך, ולכן היא נכונה גם בשורה צרה במחשב (כשהתצוגה החיה דלוקה) וגם כשהגופן במכשיר רחב יותר. הראשון בכל שורה מסומן `data-line-start`, ולו אין קו; בשורות הרווח סביב הקו קטן יותר. `watchSwitcherRow` מסדר מחדש כשסרגל ה-MD או כלי הקוד מתווספים (`MutationObserver`), וכשרוחב השורה או גודל של פריט בה משתנים (`ResizeObserver`) — אחרי `requestAnimationFrame`, כי סידור בתוך ה-callback משנה את גובה השורה שהוא עצמו מאזין לה, ונמדד שהדפדפן מדווח על זה כשגיאת "ResizeObserver loop". **נמדד ב-2026-11-04, עם אייקוני Font Awesome:** במחשב שורה אחת מרוחב 768; בטלפון, MD בשורה הראשונה מרוחב 390, וב-360 וב-375 בשורה משלו. **עד נובמבר 2026** "בטל / בצע שוב" ישבו לפני "בחר הכל", בלי קווים, ו-MD בקצה השני של השורה, עם קו לבן משלו שלא נראה בערכה בהירה.
- **ההודעה הזמנית** ("כל הקוד סומן", "הוזרק: טבלה") צפה בקצה הרווח שאחרי הכפתורים (`.editor-info-status` בתוך `.editor-info-slot`, הפריט האחרון בשורה), ואינה תופסת מקום — כך שורת הכפתורים לא משנה גובה והעורך לא זז. התא ממלא את מה שנשאר בשורה האחרונה, ולכן ההודעה לא מכסה את כפתור ה-MD. בשורה צרה הרווח קטן מההודעה, והיא מכסה לכמה שניות חלק מהכפתורים שלפניה; יש לה רקע, ו-`pointer-events: none` משאיר אותם לחיצים. **אין יותר תווית "קיצורי מקלדת זמינים"** (נובמבר 2026): היא תפסה רוחב שכפתורי "בטל" / "בצע שוב" צריכים. עד אז ההודעה ישבה במקומה, והתווית היא שהחזיקה לה את המקום — בלעדיה, הודעה הורידה את העורך (נמדד: 17px בעורך הציבורי ברוחב 1024, 31px בעמוד העריכה ברוחב 820), ולכן ההודעה צפה. בעורך הפשוט נשארה התווית "עורך טקסט בסיסי", באותו תא (`updateInfoBanner`).
- **התווית של שדה הקוד** — "קוד" בעמודי העריכה וההעלאה, "Markdown" בעורך הציבורי — מוסתרת מהעין (`sr-only`) ונשארת לקורא מסך. היא לא נמחקת: `addSwitcherButton` מציב את שורת הכפתורים מיד אחריה. עד נובמבר 2026 בעמודי העריכה וההעלאה היא הייתה שורה גלויה מעל העורך.
- **"בטל" ו"בצע שוב"** — שני כפתורים, אייקון בלי טקסט, בקבוצה משלהם אחרי "בחר הכל / העתק / הדבק" בכל עמודי העורך (`.btn-editor-undo` / `.btn-editor-redo` בתוך `.editor-history-actions`, ב-`addSwitcherButton`). הם מפעילים את `undo` / `redo` של ההיסטוריה של CodeMirror, אותן פקודות ש-`historyKeymap` של `@codemirror/commands` מפעיל ב-Ctrl+Z / Ctrl+Y (נבדק בגרסה 6.10.0), ולכן הכפתור והמקלדת עובדים על אותה היסטוריה. כפתור מושבת כשאין לו מה לעשות (`undoDepth` / `redoDepth`), והמצב מתעדכן אחרי כל עדכון של העורך (`getHistoryButtonsExtension`) ובכל החלפת עורך (`syncHistoryButtons`). הלחיצה לא לוקחת את הפוקוס (`preventDefault` על `mousedown`): הסמן לא נכנס לעורך, ובטאבלט לא נפתחת מקלדת, ואם הסמן כבר בעורך הוא נשאר שם. בעמוד מימין לשמאל החצים בתמונת ראי, כך שהחץ של "בטל" פונה ימינה (`codemirror-custom.css`). ארבע הפקודות מיוצאות ב-`window.CodeMirror6`, מהחבילה המקומית וממסלול ה-CDN של `loadCodeMirror`. **בעורך הפשוט הקבוצה מוסתרת** (`syncHistoryButtons` מסתיר את `.editor-history-actions`, ולכן גם הקו שלפניה נעלם): ל-textarea אין היסטוריה משלו, וה"בטל" של הדפדפן (`document.execCommand('undo')`) הוא מחסנית אחת לכל העמוד. נמדד בכרומיום, בעמוד העריכה: אחרי הקלדה בעורך ואחריה בשדה שם הקובץ, הוא ביטל את מה שהוקלד בשם הקובץ, גם כשהפוקוס הועבר קודם ל-textarea; והוא העביר את הפוקוס ל-textarea, כלומר בטאבלט היה פותח מקלדת. ההסבר בקוד — ב-`runHistoryCommand`.

## שמירת העדפות משתמש – שני נתיבי API
כדי לשמור תאימות לאחור, מומלץ לכתוב לשני נתיבים:
- `POST /api/ui_prefs`
- `POST /api/user/preferences`

```javascript
async function savePrefs(prefs) {
  const body = JSON.stringify(prefs);
  const headers = { 'Content-Type': 'application/json' };
  // כתיבה לשני מסלולים (best-effort)
  await Promise.allSettled([
    fetch('/api/ui_prefs', { method: 'POST', headers, body }),
    fetch('/api/user/preferences', { method: 'POST', headers, body }),
  ]);
}

savePrefs({ wrap: true, fontSize: 14, theme: 'ocean' });
```

שדות טיפוסיים: `wrap`, `fontSize`, `theme`, `tabSize`.

## המלצות
- אחסון לוקאלי משלים (`localStorage`) להאצת טעינה.
- ולידציה צד־שרת לערכים חריגים.
- לוגים מאוחדים עם `request_id` עבור פעולות עריכה ושמירת העדפות.
