:summary: חלון הייצוא של המחוברים בונה את הקובץ בדפדפן, באותו מנוע כמו התצוגה החיה, והשרת מגיש שלד עם שם הקובץ והערכה. מאיפה מגיע הטקסט, איך המנוע נטען רק בלחיצה, איך נקבעים ערכת ה-Mermaid וצבעי התחביר, המתג שמחזיר את הבנייה לשרת, ומה עדיין נבנה בשרת.

.. _styled-export:

ייצוא HTML מעוצב מעמוד הקובץ
==============================

בעמוד של קובץ Markdown (``/file/<file_id>``), למשתמש פרימיום או לאדמין, "HTML מעוצב" פותח את חלון הייצוא: ערכות מוכנות, הערכות של המשתמש, וייבוא של ערכת VS Code לייצוא אחד. "תצוגה מקדימה" פותחת את הקובץ בטאב חדש, "הורד HTML" מוריד אותו, ו"העתק קישור" יוצר קישור שיתוף. החלון הוא ``webapp/templates/export/export_modal.html``, והלוגיקה שלו ב-``webapp/static/js/export-modal.js``.

"תצוגה מקדימה" ו"הורד HTML" בונים את הקובץ **בדפדפן**, באותו מנוע כמו התצוגה החיה וכמו הייצוא מהעורך הציבורי (:ref:`העורך הציבורי <webapp-markdown-editor-export>`), ולכן מה שנראה בתצוגה החיה הוא מה שיוצא: התראות, מארקר, צ'קליסט, נוסחאות ותרשימים. קודם השרת המיר את הקובץ ב-Python-Markdown, שאינו מכיר חלק מהתחביר הזה, והקובץ שיצא היה שונה מהתצוגה.

הזרימה
-------
הזרימה זהה לזו של העורך הציבורי, והחלקים המשותפים לשניהם ב-``webapp/static/js/utils/styled-export-core.js`` (``window.StyledExportCore``):

1. ב"תצוגה מקדימה" הטאב נפתח מיד, בתוך הלחיצה (``openPreviewTab``), מאותה סיבה כמו בעורך: דפדפן מתיר לפתוח חלון רק זמן קצר אחרי פעולה של המשתמש.
2. המנוע נטען, אם עוד לא נטען (``loadEngine``, בסעיף :ref:`styled-export-engine`).
3. הטקסט נקרא (בסעיף :ref:`styled-export-text`), ו-``MarkdownLiveRenderer.renderForExport`` מרנדר אותו לתוך אלמנט שאינו בעמוד, עם ערכת ה-Mermaid של הערכה שנבחרה.
4. רק עכשיו ידוע אם יש במסמך נוסחה, ולכן השלד מתבקש אחרי הרינדור — עם ``math=1`` כשיש, כדי לקבל את ה-CSS של KaTeX.
5. המסמך נכנס לשלד במקום ההערה (``assemble``), והקובץ מוצג בטאב או יורד (``deliver``). אחרי הורדה החלון נסגר.

הכפתורים מושבתים בזמן הבנייה, ולכל המתנה יש תקרת זמן משלה — לטעינת המנוע, לבקשת הטקסט ולבקשת השלד — כדי שבקשה שלא חוזרת לא תשאיר אותם מושבתים. כשל מוצג בחלון (``describeError``), והטאב שנפתח נסגר.

.. _styled-export-skeleton:

השלד
-----
``export_styled_skeleton`` ב-``webapp/app.py``: ``GET`` או ``POST`` ל-``/export/styled/<file_id>/skeleton``. השלד הוא העמוד המעוצב של הערכה, עם הערת HTML במקום התוכן (``EDITOR_EXPORT_CONTENT_MARKER`` ב-``services/styled_export_service.py``), באנר עם שם הקובץ, וכיתוב בתחתית (``STYLED_EXPORT_FOOTER``). הוא נבנה ב-``render_styled_export_skeleton``.

- **הרשאות כמו בייצוא שבשרת.** אין בשלד את תוכן הקובץ, רק את שם הקובץ ואת העיצוב, ובכל זאת הוא תחת אותם תנאים: התחברות, פרימיום או אדמין, וקובץ Markdown של המשתמש. קובץ שאינו Markdown מקבל 400.
- **הערכה** נקבעת כמו בייצוא שבשרת, באותה פונקציה (``_styled_export_theme_from_request``): ב-``GET`` לפי ``theme``, כולל ערכות המשתמש מהמסד; ב-``POST`` ערכת VS Code מ-``vscode_json`` שבטופס.
- ``math`` הוא ``1`` או חסר. כל ערך אחר מקבל 404.
- ``Cache-Control: no-store``, כי בשלד שם הקובץ וערכות המשתמש. ה-CSP של הנתיב הוא זה של שלד העורך (``_MARKDOWN_EDITOR_SKELETON_CSP``).
- ``X-Export-Filename`` — שם הקובץ שיורד (``styled_export_filename``), מקודד ב-URL: כותרת HTTP היא latin-1, ושם הקובץ יכול להיות בעברית. הכותרת (``styled_export_title``) ושם הקובץ נגזרים כמו בייצוא שבשרת, מאותן פונקציות.

.. _styled-export-text:

מאיפה מגיע הטקסט
-----------------
מהעמוד עצמו: ``#rawCode``, שעמוד הקובץ כבר מחזיק בשביל "העתק" והתצוגה המתקדמת. בקובץ שגדול מ-``MAX_DISPLAY_SIZE`` (ב-``view_file``) העמוד לא מציג את הטקסט ואין בו ``#rawCode``, ואז הטקסט מגיע מ-``/download/<file_id>``. שתי הדרכים מחזירות בדיוק את הגרסה שבעמוד: ``/download`` מוצא את הקובץ לפי המזהה, באותה פונקציה של עמוד הקובץ (``_get_user_any_file_by_id``). ``/api/file/<file_id>/content`` לא מתאים כאן, כי הוא מחזיר את הגרסה האחרונה של הקובץ (``_latest_file_doc_by_id``), גם כשמייצאים גרסה ישנה.

.. _styled-export-engine:

המנוע נטען רק בלחיצה
---------------------
עמוד הקובץ לא טוען את התצוגה החיה, והבאנדל שלה כבד. לכן הסקריפטים שלה יושבים בעמוד בתוך ``<template id="styledExportEngine">``, שכולל את ``_live_preview_scripts.html`` — אותה רשימה של עמודי העורך, בלי עותק שני. בתוך ``<template>`` הסקריפטים אינם נטענים ואינם רצים. בייצוא הראשון ``loadEngine`` בונה אותם מחדש כסקריפטים חיים, אחד אחרי השני, לפי הסדר.

- **ההבטחה היא השומר.** לחיצה שנייה בזמן הטעינה מקבלת את אותה הבטחה, וכשל מאפס אותה, כדי שהלחיצה הבאה תנסה שוב.
- **הבטחה לכל סקריפט.** ניסיון חוזר משתמש במה שכבר נטען, ובונה מחדש רק את מה שנכשל — בלי להריץ את הבאנדל פעמיים.
- **תקרת זמן אחת לטעינה כולה**, ולא לכל סקריפט.

``tests/sticky-notes-target.test.js`` בודק שהתוכן של ``#styledExportEngine`` הוא ה-partial בלבד, ושה-partial אינו נכלל בעמוד גם מחוץ ל-``<template>``.

ערכת ה-Mermaid וצבעי התחביר
-----------------------------
התרשימים מצוירים לפני שהשלד מגיע, ולכן ערכת ה-Mermaid מגיעה לדפדפן עם רשימת הערכות: ``mermaid_theme`` ב-``/api/export/themes``, לכל ערכה מוכנה ולכל ערכת משתמש, וב-``/api/export/parse-vscode`` לערכת VS Code. ההכרעה ב-``export_mermaid_theme``: לפי ``category`` של הערכה, ולערכת משתמש, שאין לה קטגוריה שמורה, לפי הבהירות של ``--bg-primary`` — באותה נוסחה ובאותו סף כמו ``pageMermaidTheme`` ב-``live-preview.js``. העורך הציבורי מכריע באותה פונקציה.

צבעי התחביר בקובץ הם של highlight.js, כמו בתצוגה. לערכות הייצוא של העורך יש כללים משלהן (``hljs_css``). ערכה מיובאת מ-VS Code שומרת כללים תחת הקידומת של האתר, והם עוברים לקידומת של הייצוא (``rebase_hljs_css``). לכל ערכה אחרת — הפלטה שנגזרת מהמשתנים, כמו בתצוגה (:doc:`theming_and_css`).

.. _styled-export-switch:

המתג
-----
``STYLED_EXPORT_BROWSER_RENDER`` (ברירת מחדל ``true``, :doc:`../environment-variables`). ב-``false`` "תצוגה מקדימה" ו"הורד HTML" חוזרים לייצוא שבשרת, ``/export/styled/<file_id>``, שנשאר כמו שהוא. זו דרך חזרה בלי דיפלוי של קוד.

- הערך מגיע לחלון דרך ``inject_globals``, כ-``data-browser-render``, יחד עם טקסט ההערה של השלד (``data-content-marker``).
- **הוא נכנס ל-ETag של עמוד הקובץ.** בלעדיו, עמוד שמור היה מקבל 304 אחרי היפוך המתג, וממשיך במסלול הקודם.
- ``export-modal.js`` חדש מול עמוד ישן, בלי המאפיינים או בלי ``styled-export-core.js``, עובד במסלול של השרת.

מה עדיין נבנה בשרת
-------------------
"העתק קישור" יוצר קישור שיתוף (``/api/export/styled/<file_id>/share``), והשרת שומר בו את ה-HTML שהוא בנה ב-Python-Markdown (``render_styled_html``). הקישור נפתח בדפדפן של מי שקיבל אותו, בלי חשבון, ולכן הוא לא עובר דרך החלון.
